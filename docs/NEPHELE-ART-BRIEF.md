## 1. 参考图 DNA 拆解（拿什么、翻译什么、丢什么）

参考图（蓝发少女三视图）本 Boss **不能照搬题材**，只能搬它的**视觉语言**。逐条拆：

### 1.1 直接拿（决定画面气质）

| 参考图元素 | 应用到云鲸 |
|---|---|
| 三视图横排、中性灰底、无文字无边框 | 出图版式，本文 §4 硬规范 |
| 冰蓝 `#A9CDEA` + 珍珠白 `#F2F6FA` + 冷调高光 | 主色板，本文 §6 |
| 头顶光环（细环、悬空、微倾、发光） | **鲸的光环**：直径 2.6、悬于头顶上方 0.6 格、后倾 12° |
| 缎带 / 飘带（蓝白渐变、末端收窄、几何切角） | 尾部两侧 **2 条云缎飘带**，从尾根垂下、末端切角 |
| 晶片层叠（衣片/裙摆都是硬边多边形，边缘一圈亮线） | 背甲 4 片 + 背鳍 5 片 + 尾帘 3 段，**每片一圈发光描边** |
| 赛璐璐平涂 + 硬边高光 + 少量渐变 | 三视图着色方式（见 §9 画风说明） |

### 1.2 必须翻译（换载体，保留逻辑）

| 参考图 | 云鲸上的对应物 | 为什么 |
|---|---|---|
| 少女体型 / 裙摆 | 鲸形躯干 + **尾帘**（3 段下垂的宽尾鳍，像裙摆） | Boss 是鲸，剪影必须横向流线 |
| 双马尾缎带 | 尾根两条飘带 + 背鳍边缘的细飘带 | 保留「飘」的动态语言 |
| 发丝分缕 | 背鳍 5 片，每片再切 2–3 道分叉 | 分缕 = 可数的层叠 |
| 靴子（白底 + 蓝晶块 + 环扣） | **腹部 5 道褶 + 尾端散热环**（环状结构 + 晶格块） | 环扣语言落到散热口上 |
| 关节点缀的菱形宝石 | 体表 6 处寄生晶簇 + 肩鳍根部各 1 颗 | 唯一的高饱和重点 |

### 1.3 丢掉

- 人脸、皮肤、腿部、裙子本体 —— 云鲸没有这些，**不要**为了「像参考图」强行加人形上半身；
- 头发的刘海分缝逻辑 —— 鲸头是钝圆吻端，只有两道细眼缝。

### 1.4 参考图没给、但本 Boss 必须有

1. **长尾**（尾端 = 常驻弱点，判定在 z=+4.2 / y=0.8，尾必须够长且**下垂**才能把散热环放到那么低的位置）；
2. **背部两个气囊**（P3 弱点，判定在 y=2.2 而不是背脊顶端 —— 见 §8 的坐标冲突说明）；
3. **4 片可打掉的护甲板**（独立血量，必须有完好/裂开两档）；
4. **雷云紫**（血条是紫的，P2 的雷必须与血条同族）。

## 2. 定位与尺度（单位：方块；局部坐标 **−Z = 正面**，原点 = 实体脚底 y=0）

### 2.1 视觉尺寸表

| 部位 | 数值 | 说明 |
|---|---|---|
| 总高 | **5.6**（y 0 → 光环顶） | 满足「4–6 格巨型」 |
| 主体高 | 3.4（y **1.2 → 4.6**） | 悬浮：腹底离地 1.2 |
| 体长 | **9.5**（吻端 z=−5.0 → 尾端 z=+4.5） | 长:高 ≈ 2.8:1，鲸的比例 |
| 躯干段 | z −4.4 → +2.6（长 7.0） | 前中后 3 段，接缝处收窄 12% |
| 尾段 | z +2.6 → +4.45，**下垂**（y 3.0 → 0.8） | 尾端必须落在 (0, 0.8, +4.2) |
| 翼展 | **8.8**（x ±4.4） | 侧鳍薄膜可超判定箱 |
| 头高 | 1.6（占主体 47%） | 钝圆、吻端平切 |
| 光环 | 直径 **2.6**、环体厚 0.16、中心 y=**4.95**、后倾 **12°** | 正视呈扁椭圆（宽 2.6 / 高 ≈0.55） |

### 2.2 判定箱建议

| 项 | 现状 | 建议 | 理由 |
|---|---|---|---|
| `EntityType.sized` | `(7.0F, 4.0F)` | **`(7.0F, 4.8F)`** | 主体顶到 y=4.6，4.0 高的箱子会让箭矢穿过背甲上部与背鳍根部 |
| `eyeHeight` | `2.6F` | `3.2F` | 视点抬到躯干中线，锁敌与抬头角更自然 |
| 翼展 ±4.4 / 光环 y 4.4–5.5 | 超出判定箱 | **不扩大**，视为美术豁免 | 侧鳍是半透明云膜、光环不是肉体；不要让玩家在模型外 1.5 格处空手打空气 |

> 这两行改动在 `ModEntities` 里就是两个数字，**风险只在贴顶飞行时的碰撞**（金星云海空旷，可接受）。

## 3. 剪影规范

### 3.1 与另外三个 Boss 的区分（压成纯黑仍可辨）

| Boss | 剪影特征 |
|---|---|
| **涅斐勒** | **横向流线 + 一枚悬空的环**（别的 Boss 头顶都没有东西）+ 下垂长尾 |
| 赫菲斯托斯 | 纵向厚重、宽肩、拳过大、短腿 |
| 阿佛洛狄忒 | 上窄下宽、融化的裙柱 |
| 阿瑞斯 | 人形机械、肩甲外扩 |

### 3.2 剪影禁忌

- ❌ 光环不要做成实心圆盘 / 粗箍 —— 必须是**细环**，否则剪影变成「戴帽子」；
- ❌ 尾巴不能短、不能水平伸直 —— 必须**先横向延伸再向下垂**，尾端散热环落在 y≈0.8，否则弱点位置没有落点；
- ❌ 不能做成「会飞的鱼」（细长、无厚度）—— 躯干横截面要圆润有体积；
- ❌ 侧鳍展开角不要超过 ±35°（超过就变成蝠鲼 / 鳐）；
- ❌ 背鳍不超过 5 片且单片长度 ≤1.2 格（多了就是鱼鳍阵列）。

## 4. 三视图版式硬规范（**这就是「一次性出一张类似参考图布局的图」的规格**）

### 4.1 画布

| 项 | 规定 |
|---|---|
| 比例 / 尺寸 | **16:9**，2000×1125（或与参考图一致的 1619×971） |
| 背景 | 中性灰 **`#6C7078`**，纯色，**无渐变、无地平线、无落地投影、无雾气** |
| 布局 | 三视图**横排等距**：左=正面、中=侧面（头朝画面左）、右=背面 |
| 间距 | 视图之间留 ≈ 主体宽度的 0.6 倍 |
| 比例一致 | 三视图**同一缩放**，不许各自适配 |
| 基线 | 三视图共用一条**隐形地面基线**：主体下缘距基线 1.2、尾端环距基线 0.8、光环顶距基线 5.6 |
| 投影 | 正交投影（orthographic），机位水平，**无透视缩短、无仰俯** |
| 光照 | 左上 45° 主光 + 冷色环境光（`#BFD8F0`）+ 底部微弱反弹光；背面视图要能看到轮廓光 |
| 文字 | **无文字、无标注、无箭头、无水印、无边框、无 logo** |
| 画幅占比 | 主体高占画布高度 **72–78%** |

### 4.2 每个视图必须能看到什么（少了就是不合格）

**① 正面（z 轴正对镜头，吻端朝观众）**
- 光环：扁椭圆，悬在吻端上方，环心略高于头顶；
- 吻端：钝圆、**平切的下颌线**，两道横向细眼缝（无瞳孔、无高光点）；
- 侧鳍：左右对称展开到 ±4.4，薄膜半透明，翼膜内可见 3–4 道骨架分叉；
- 尾：从躯干下方**垂直下垂**，正视看到尾端散热环的**正面环口**（一圈橙色发光，环内暗）；
- 背部气囊：被躯干挡住，看不见（→ 正视图靠「光环 + 翼展 + 尾环」三件辨识）；
- 腹部 5 道褶：可见中 3 道，横向弧线。

**② 侧面（头朝画面左，最能读结构，也是最严格的一张）**
- 悬浮高度 1.2（腹底与基线之间的空隙必须看得出来）；
- 吻端钝圆 → 头顶隆起 → 背脊 4 片甲壳接缝 → 尾根 → 3 段下垂尾帘；
- 背鳍 5 片，从头顶后方到腰后，前高后低、依次变短，薄膜半透明；
- 背部气囊 2 个，位于**躯干中线偏上、y=2.2**（不是背脊顶端！），半透明白；
- 尾部：先横向延伸到 z≈+3.0，再下折，尾端散热环在 y≈0.8，环内橙光；
- 腹部 5 道褶全部可见；
- 侧鳍：只看到近侧一片，向前下方斜伸（约 −20°）。

**③ 背面（z 轴背对镜头）**
- 4 片护甲板：从背脊中线向两侧铺开，**接缝清楚可数**（这是「4 板独立血量」的唯一视觉依据）；
- 两个气囊：正对镜头，是背面最大的两个圆形高光面；
- 光环：正面看到环的内壁与环背；
- 尾端散热环：看到环的外缘与一层层收拢的鳍片（背面朝观众）；
- 两条云缎飘带：从尾根两侧垂下，末端切角，蓝白渐变。

### 4.3 不要的东西
- 不要额外加「战斗姿态」「阶段变体」「弱点特写」——**这一张只出三视图**；阶段与特写另案（见 §7、§8）。

## 5. 结构拆分与骨骼（GeckoLib 命名，≥48 个部件）

### 5.1 骨骼树

```
root
└─ body                     躯干主骨（悬浮起伏/俯冲整体转向）
   ├─ body_front            前躯干（吻端后 z −4.4 → −1.6）
   │  ├─ head               头（钝圆 + 下颌）
   │  │  ├─ jaw             下颌（云爆弹张口）
   │  │  ├─ muzzle_plate    吻端平切板（晶片）
   │  │  ├─ eye_slit_l/_r   两道横向眼缝（发光，emissive）
   │  │  └─ crest           头顶冠片 3 片
   │  └─ fin_l / fin_r      侧鳍根（绕 z 轴扇动）
   │     ├─ fin_membrane    半透明云膜（双面）
   │     └─ fin_rib_1..4    翼膜骨架分叉
   ├─ body_mid              中躯干（4 片护甲板挂这里）
   │  ├─ plate_1..4         护甲板（独立骨 → 独立破碎动画）
   │  ├─ dorsal_fin_1..5    背鳍
   │  ├─ belly_fold_1..5    腹褶
   │  └─ sac_l / sac_r      气囊（P3 膨胀；内含 sac_core_l/_r 发光核）
   ├─ body_rear             后躯干（z +1.0 → +2.6）
   ├─ cloud_veil            云膜外壳（半透明包覆层，不参与判定）
   └─ tail_1 → tail_2 → tail_3 → tail_tip
      ├─ tail_fin_l / _r    尾帘 3 段（各 2 片）
      ├─ ribbon_l / ribbon_r 云缎飘带 ×2
      └─ tail_vent_ring     尾端散热环（**常驻弱点**，中心必须落在 (0,0.8,+4.2)）
         └─ vent_glow       环内橙光（emissive）
```

### 5.2 部件预算

| 类别 | 数量 | 备注 |
|---|---|---|
| 主体块 | 12 | 躯干 3 段 + 头 + 下颌 + 吻板 + 尾 4 段 + 尾帘 3 |
| 护甲板 | 4 | **必须能单独隐藏**，与 4 板血量一一对应 |
| 鳍 / 膜 | 5 背鳍 + 2 侧鳍（各含 4 道骨架）= 15 | 侧鳍用 `add_wing` 或半透明 mesh |
| 褶皱 / 环 / 晶簇 | 5 腹褶 + 1 散热环（含 12 片环鳍）+ 6 晶簇 = 24 | 散热环环鳍用 `generate_array` 径向排布 |
| 发光件 | 2 眼缝 + 2 气囊核 + 1 尾焰 + 光环 3 段 = 8 | 全部走 glowmask，不另开贴图 |
| **合计** | **≈ 58**（远超 Boss 门槛 42） | 细节密度目标：`audit_complexity` 判 high_detail |

### 5.3 建模硬规则

- 全部走 **Blockbench → GeckoLib geo**（同 `hephaestus.geo.json` 管线），`grep` 可对照 `HephaestusModel`；
- 光环 = 独立骨 `halo_ring_a/b/c`（3 段，P2 可分裂旋转），**不绑在 head 上**（head 会随目标转动，光环不能跟着点头）；
- 尾端环、气囊、尾焰三点与 §8 的弱点坐标**逐格对齐**，建模完成后用 `measure_model` 反查；
- 半透明云膜/侧鳍用 `RenderType.entityTranslucent`（照 `AresRenderer` 的 `ShieldLayer` 写法），主体仍走 `entityCutoutNoCull`；
- 发光件统一进 `nephele_glowmask.png`，渲染器加 `AutoGlowingGeoLayer`（照 `HephaestusRenderer`）。

### 6.2 用色纪律

1. **暖色只有一个出口**：尾部散热环。别在别处撒橙。
2. **P3 的高亮权让给气囊**（黄绿白），尾焰那时要**暗下去**——这样玩家能读懂「换阶段了」。
3. 冷色分三档明度（`#F2F6FA` / `#A9CDEA` / `#3E6E9E`），**不要中间调堆三层以上**，否则远看成一坨蓝。

## 8. 弱点可视化（与代码坐标逐格对齐）

### 8.1 对齐表（局部坐标，−Z = 正面，y 自脚底）

| 弱点 | 代码偏移 | 半径 | 美术要求 |
|---|---|---|---|
| `tail_vent`（常驻） | **(0, 0.8, +4.2)** | 1.2 | 尾端散热环的**环心**必须落在该点 ±0.3；环面朝 +Z（背面），环内 `#FF8A3C` emissive，环外一圈 12 片收拢鳍（金属冷灰 + 被烤黑的皮肤） |

| `air_sac_right`（P3） | **(+1.6, 2.2, −0.4)** | 1.2 | 同上镜像 |

**注意 ± 符号**：代码里 left 是 **x = −1.6**。模型里模型自身右侧是 +X，别做反。

### 8.2 ⚠ 现有代码冲突（美术无法修，必须改代码）

`AbstractBossEntity.tryHitWeakPoint()` 第 357 行：

```java
Vec3 world = this.position().add(weakPoint.offset());
```

弱点偏移**直接按世界轴相加，没有按 `yBodyRot` 旋转**。后果：

- 鲸转向玩家后，尾巴转到别的方向，但那颗命中球永远停在实体**世界 +Z** 侧；
- 也就是说「看到尾巴 = 能打弱点」只在鲸朝正北（yaw 0）时成立，其余朝向全部错位最多 8 格。

**建议补丁**（局部 → 世界，yaw 取 `yBodyRot`；在 `yaw=0` 时结果与现状一致，`yaw=90` 时局部 +X → 世界 −Z）：

```java
double y = Math.toRadians(this.yBodyRot);
double cos = Math.cos(y), sin = Math.sin(y);
Vec3 o = weakPoint.offset();
Vec3 world = this.position().add(
        o.x * cos + o.z * sin,
        o.y,
       -o.x * sin + o.z * cos);
```

改完后必须做的验证：`F3+B` 看主判定箱 + 站到鲸的**正面 / 侧面 / 背面**各射一箭，确认命中球跟着尾巴走（否则三视图把尾环画得再准也没用）。

### 8.3 视觉要求（铁律）

- 常驻弱点 = **发光开口**（尾环内橙光），不能只是一块染色；
- 阶段弱点 = **平时关闭、开阶段时打开**（气囊必须有膨胀动画 + 盖片张开），不能只换贴图；
- 全身**只允许一个最亮点**：P1/P2 是尾焰，P3 是气囊。
