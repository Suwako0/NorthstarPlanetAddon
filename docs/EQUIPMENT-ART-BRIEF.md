# 启明星附属 · 武器装备美术需求案 v1.0

> **范围**：`northstar_planet_addon` 除月球线外的全部**武器、工具、护甲、随身装备**（火星线 + 金星线，水星线空缺见 §4.6）。
> **不含**：月球线（`moon_deer_axe` 等一律不动）、材料、食物、刷怪蛋、方块。
> **读者**：主美 / 像素美术 / 3D 建模（Java 模型）/ 负责集成的程序。
> **配套文档**：逐件 UV 与部件表见 `docs/<物品名>-atlas.md`、`docs/<套装名>-armor.md`；生成链见 `docs/EQUIPMENT-REDO.md`。
> **性质**：这是**整体重做**的需求案，不是补漏。现存 45 件装备资源全部是程序占位（可玩、不达标），其中五套护甲的 `layer_2` 实测为空白（§3.3.1）。

## 0. 怎么用这份文档

1. **先读 §1–§3**：这三节是硬约束（风格、符号、尺寸、绘制规则）。任何一件不遵守都会在验收被驳回。
2. **再抽 §4 对应卡片**：一张卡 = 一件交付物（或一组同构件），可直接派工。
3. **按 §5 自检**再提交，**按 §6 排期**。
4. 文案里的数值（伤害、攻速、护甲值）不是给美术看的数值表，而是用来判断**视觉重量**的：伤害 20 的重炮不能画成玩具。

## 1. 世界观与美术基调

### 1.1 三个舞台，三种工业神话

| 阵营 | 环境一句话 | 美术关键词 | 现实参照 | 反例（不要画成） |
|---|---|---|---|---|
| **火星** | 锈红荒原、熔炉与战神阿瑞斯的祭坛 | 熔铸、黑曜石、余烬、青铜战神纹样 | 火山岩 + 高炉出钢口 + 中世纪重甲 | 干净光滑的科幻机甲 |
| **金星（钨钢/压力）** | 90 bar 硫酸云海，人类靠压力服活着 | 压力容器、密封圈、铆接板、保养油污 | 深海潜水服 + 蒸汽管道 + 老式压力表 | 发光能量线条的太空服 |
| **金星（云海/熔管）** | 云城遗迹与地下熔岩管道 | 云帆膜、气囊、黄铜仪表；重板甲、排酸沟槽 | 飞艇 + 熔岩管 + 防化服 | 天使翅膀、纯装饰性飘带 |
| **金星（启明星）** | 前文明遗产 + 黎明神性，终局 | 金、黎明玫瑰、光环、宝石镶嵌 | 圣像画的金箔 + 天文仪 | 全身发光的"能量体" |

**统一前提**：这是一个**工业文明**的装备库。所有华丽感必须来自**结构上的装饰**（包边、箍环、铆钉、镶嵌槽、绶带、铭牌），不能来自"发光的魔法花纹"。发光是稀有度奖励，不是基础装饰。

### 1.2 上一轮的问题诊断（这是本次的硬性修正）

上一轮启明星盔甲的失败点，逐条对应下面的规则，**全部为红线**：

| # | 问题 | 修正规则 |
|---|---|---|
| R1 | 装饰靠"堆盒子"，看起来是把方块粘在甲上 | **每件装饰必须能说出结构理由**（固定、防护、铰接、配重、徽记）。说不出理由的盒子删掉 |
| R2 | 金 / 青 / 紫三色平摊，色相打架 | **一套装备最多 2 个色相**。第三色仅限宝石或发光件，面积 ≤10% |
| R3 | 发光色铺成大色块，整体发灰发脏 | **发光只做点、线、缝**，单块面积 ≤4×4 px；发光必须有一圈暗部做对比 |
| R4 | 金属只有一种明度，没有高光/暗部 | 每块金属面至少 **3 阶明度**（暗部 / 中间调 / 高光边），且高光统一朝左上 |
| R5 | 左右对称件完全相同，缺细节 | 对称件**轮廓对称、细节不对称**（一侧多一道刻痕 / 一颗铆钉偏移） |
| R6 | 装饰件与穿戴层色系脱节，像拼贴 | 装饰图集与 `layer_1` 必须**共用同一套调色板**，跨图集取色 |
| R7 | 五套甲用同一张形状，只换颜色 | **每套必须有自己的剪影**（肩/腰/领/下摆四项至少两项不同），实测差异见 §3.3.1 |
| R8 | 护腿用的 `layer_2` 几乎是空图 | `layer_2` **必须重画**并覆盖腿部四面，否则护腿在游戏里等于没穿 |

### 3.3 穿戴层布局（原版模板，严格对齐）

两张图都是 **64×32**，位置由原版 `HumanoidModel` 的 box UV 决定，**不许改布局**，只许改内容。
**哪件甲读哪张图是写死的**：

| 装备部位 | 读哪张 | 说明 |
|---|---|---|
| 头盔 / 胸甲 / 靴子 | `layer_1` | 头盔、躯干、四肢的外表面 |
| **护腿** | **`layer_2`** | 只读 `layer_2`，`layer_1` 画得再漂亮护腿也用不上 |

**layer_1 区域（实测占位）**

| 区域 | 像素矩形 | 内容 |
|---|---|---|
| 头盔 | `(0,0)–(32,16)` | 六面展开；**正面 = `(8,8)–(16,16)`** |
| 躯干 | `(16,16)–(40,32)` | 胸/背/侧四面 |
| 右臂 | `(40,16)–(56,32)` | 上臂 + 前臂；`(40,26)` 以下为手部，必须空 |
| 腿（仅靴子用） | `(0,16)–(16,32)` | 左右腿共用，另一侧走镜像 |
| 左臂 | — | 镜像复用右臂区域，**不要另画** |

**layer_2 区域（护腿专用）**

| 区域 | 像素矩形 | 内容 |
|---|---|---|
| 右腿 | `(0,16)–(16,32)` | 大腿 + 小腿正面/侧面/背面（box UV 展开） |
| 左腿 | 镜像 | 复用同一块，**不要另画** |
| 腰部 | `(16,16)–(40,32)` | 护腿的腰/裆部 |
| 空白区 | 其余 | 保持全透明 |

**必须镂空**

| 位置 | 矩形 | 现状 |
|---|---|---|
| 脸部开口 | `(8,9)–(16,15)`，保留 `y=8` 与 `y=15` 各 1 px 作头盔边沿 | 已挖空，但 `y=10` 残留 4 px（`x=9,10,13,14`）暗色点，**正好压在眼睛行** |
| 右手 | `(40,26)–(56,32)` | 已挖空 |

> **违反镂空 = 玩家看不见自己的脸和手**，这是本模组历史上被驳回次数最多的一条。
> `y=10` 那 4 个点要么删干净，要么明确画成"眉线"（加 1 px 高光让它有意图），不要留成无意义的脏点。

### 3.3.1 现状体检（2026-11 实测，美术接手前必读）

用脚本逐像素比对五套 `layer_1/2`，结果如下——这就是"五套甲看着像同一套"的物理原因：

| 检查项 | 实测结果 | 结论 |
|---|---|---|
| 五套 `layer_1` 的 **alpha 掩膜** | **逐像素完全相同**（每张仅 1364 个不透明像素，差异 0） | 五套共用同一张形状，**只换了颜色** |
| 五套 `layer_2` 的 alpha 掩膜 | 除 `phosphoros`（本轮改过 35 px）外全部相同 | 同上 |
| `layer_2` 的不透明像素总数 | **176 px**（整张 64×32 只有 176 个），且只有 `y=0–1` 与 `y=16–17` 两条 2 px 高的横带 | **护腿在游戏里几乎不可见** —— 这是必须优先修的硬伤 |
| `layer_1` 覆盖率 | 1364 / 2048 = 67% | 甲面偏薄，胸口与四肢大面积留白 |

**因此本轮要求**：
1. `layer_2` **从零重画**（不是在上面的横带上补），必须覆盖 `(0,16)–(16,32)` 的腿部四面 + 腰部；
2. 五套 `layer_1` **必须画出各自不同的剪影**（肩线、腰线、下摆长度、护颈高度各不相同），不能只换颜色；
3. 每套 `layer_1` 的不透明像素数应落在 **1600–1900**（留出脸部开口与手部）。

### 3.4 盔甲装饰图集（128×128）

- UV 偏移量**直接按像素计**（`LayerDefinition.create(mesh, 128, 128)` + `texOffs(x, y)`）。
- 每块装饰的坐标以 `docs/<set>-armor.md` 的部件表为准，**留 1–2 px 边距**，不得压到邻块。
- 装饰图集与 `layer_1/2` **必须同调色板**（R6）。取色方式：先在 layer 上定甲面 3 阶明度，装饰件用同阶的亮阶 + 强调色。

### 3.5 绘制规范

1. 色板 **≤8 色**（含透明），且必须来自 §1.4 / §7A 的调色板；新色需在 §7A 登记。
2. **禁用渐变抖动**（dithering）：明度过渡靠"整块提亮 1 阶"，不靠噪点。
3. 光源**统一左上**；高光边只在左上缘，暗部只在右下缘。
4. 图标：主体外轮廓 **1 px 深色描边**（`#14100e` 系，不用纯黑），主体占 12×12，右上 4×4 留空给高阶稀有度特效。
5. 金属面**禁止大面积镜面白**；高光用 `-h` 阶，不用纯白（纯白仅限发光芯）。
6. 对称件：轮廓镜像，细节手工打散（R5）。

### 3.6 模型侧约束（建模/集成读）

| 约束 | 值 | 理由 |
|---|---|---|
| 每把武器 element 数 | ≥45（硬下限 35） | 低于 35 会读成"玩具" |
| 握把中心 | 精确 `(8,8,8)` | 物品渲染支点，偏了会浮在手外 |
| `display.thirdperson` | `translation [0,1,0.5]`、`rotation [0,∓90,55]`、`scale 0.85`（长柄 0.75） | 与 3D 握持对齐，**禁止**套用 2D 图标的 `[0,4,0.5]` |
| `display.gui` | 按包围盒缩到 15/16 格并居中 | 否则物品栏溢出 |
| 装饰模型 `renderToBuffer` | **只画装饰件**，身体交给 `layer_1/2` | 重画身体会导致"看不见脸/手" |
| 模型 UV | 重画贴图**不改 UV** | 改 UV 要连带改模型，成本翻倍 |

### 3.7 命名与提交

- 文件名 = 物品注册名，全小写下划线，**不建子目录、不加版本后缀**（`molten_core_sword.png`）。
- 一个物品的全部资产（图标/图集/层/图集/模型）必须**同一次提交**，避免半套资源。
- 提交信息：`art(<阵营>): <物品名> <类型> rev<N>`，例：`art(venus): acidic_spear atlas rev2`。

### 4.1 火星线（熔炉 / 战神）

## 5. 交付与验收流程

### 5.1 三审制（每件资产必须过三关）

| 关 | 内容 | 通过标准 |
|---|---|---|
| **一审 · 灰阶** | 只交黑白剪影（无颜色、无细节） | 缩小到 25% 仍能认出物品类别 |
| **二审 · 色稿** | 上色 + 材质分层 | 命中 §1.4 调色板，色相 ≤2，发光面积达标 |
| **三期 · 引擎内** | 进游戏截图（物品栏 / 手持第三人称 / 穿戴 3/4 视角） | 无穿模、脸手可见、图标不溢出格子 |

**任何一关不通过就回到上一关，不要"边过边改"。**

### 5.2 自检清单

**通用（每件）**
- [ ] 尺寸与路径与 §3.1 完全一致
- [ ] 色板 ≤8 色，全部来自登记调色板
- [ ] 无渐变抖动、无抗锯齿、无预乘 alpha
- [ ] 光源统一左上，高光只在左上缘
- [ ] 装饰件能说出结构理由（R1）
- [ ] 对称件细节已打散（R5）

**图标**
- [ ] 主体占 12×12，右上 4×4 留空
- [ ] 1 px 深色描边，无纯黑
- [ ] 25% 缩放可辨类别

**武器图集**
- [ ] 8 个区域无跨区串色，区块间 ≥2 px 空带
- [ ] 边缘 4 px 内无细节
- [ ] 未改动模型 UV

**盔甲**
- [ ] 脸 `(8,9)-(16,15)` 与右手 `(40,27)-(56,32)` 已镂空
- [ ] 装饰图集与 layer 同调色板（R6）
- [ ] 四件图标同色阶
- [ ] 3/4 视角无穿模、无"实心方块"

### 5.3 常见驳回原因（历史高频）

1. **脸/手被糊住** —— 忘镂空，或把 `_armor.png` 当 layer 用。
2. **图标右上方被占** —— 物品栏里与数量角标打架。
3. **图集跨区串色** —— mipmap 把邻区颜色吸过来，边缘出现脏边。
4. **发光铺满** —— R3 违规，游戏里会糊成一片。
5. **四件甲不是一套** —— 分别独立配色调，缺 R6 统一。
6. **3D 武器握把不居中** —— 握把中心不在 `(8,8,8)`，手上浮空。
7. **护腿是"空气甲"** —— `layer_2` 没画，或只画了几条线；护腿只读 `layer_2`（§3.3）。
8. **五套甲剪影雷同** —— 只换色不换形（R7）；验收会直接比对 alpha 掩膜。
