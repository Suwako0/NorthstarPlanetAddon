# 装备建模流水线（护甲 / 武器 / 工具 / 饰品）

一句话：**几何与贴图的唯一来源是 `.bbmodel`，游戏内资源由脚本从它导出**。任何"手写坐标 + 另画一套贴图"的做法，最终都会得到两个互不相干的模型——装备尤其致命，因为它同时受模型、贴图、槽位、持握姿态四套东西约束。

## 0. 适用范围

| 属于本技能 | 不属于 |
|---|---|
| 护甲（穿戴层 + 3D 装饰件） | 生物 / Boss / 载具 |
| 武器、工具、法杖、盾 | 方块、机械、多方块结构 |
| 饰品、装备件、背包外挂件 | 纯 2D 图标 / GUI（走贴图技能） |

生物与方块各有自己的骨架与体积规则，套用装备规则会得到"比例正确但结构错误"的模型。

## 1. 十条铁律（每条都对应一次返工）

1. **几何只来自 Blockbench**。不手写 `from/to`、不手算 UV。改形制 = 改 `.bbmodel`，再重跑导出脚本。
2. **贴图存进 bbmodel**（`detail_cubes` / `paint_faces`）。导出时把同一张 PNG 写进 `assets/`；另画一套"游戏用图集"必然导致 Blockbench 与游戏内两副面孔。
3. **box UV 强制**（`pack_uv {mode:"box"}`）。Java 的 `elements` 和 `CubeListBuilder.texOffs` 只认盒式 UV；逐面 UV 无法转换。
4. **整数网格**：坐标与尺寸对齐 1 单位，每条边 ≥1。小于 1 的薄片会被打包成 0 像素宽的面 → 游戏里是黑面（`check_model` 报 `zero_uv`）。
5. **外扩（clearance）必须在 `pack_uv` 之前烘进几何**。打包后再改尺寸，UV 岛与盒子错位，面会采到透明像素变黑。
6. **共面即闪**。相邻件重叠 1 单位、或错开 ≥0.2；`coplanar_overlap` 必须清零，`fix_z_fighting` 后把 `inflate` **烘进导出坐标**（Java 装备模型没有 inflate 字段）。
7. **对称只做一侧**，另一侧由导出脚本按骨骼中线镜像。左右各自取整会差 0.1~1.3 单位，肉眼可见。
8. **别用会倾印全部 cube 的工具**。一次塞几十个立方体的调用，光返回值就能吃掉整段上下文；批量建模/改动用 `execute_script`，只返回计数与异常。
9. **验收顺序固定**：`check_model` → 导出 → 装备校验脚本 → `gradlew build` → `runGameTestServer`。客户端模型与贴图**不热重载**，必须重启客户端。
10. **精细度下限**：至少三层形体（剪影 → 分件 → 小件：尖角/链/铆钉/边条），2~3 个明度色调 + 1 个强调色。部件数下限见 `references/qa-checklist.md`。

## 2. 标准流程

```
0. 需求/参考图 → 定类型（穿戴 / 手持）、尺寸、骨架、材质分区、导出格式
1. new_project（free / bedrock / geckolib，按导出目标）
2. 建骨架：穿戴用原版人形六骨；手持用单骨或双骨（柄 + 刃/头）
3. 形体：大块定剪影 → 中块分件 → 小件细节
4. pack_uv(box) → detail_cubes 按名字前缀上色
5. check_model → fix_z_fighting → 重新 pack_uv → 重新上色
6. save_project → docs/models/<name>.bbmodel
7. 脚本导出：贴图 + 每个 cube 的 uv_offset + 尺寸 → Java/JSON
8. 校验脚本 → build → GameTest → 截图（Blockbench 与游戏内各一张）
```

第 5 步不能省：改过几何就必须重打包并重新上色，否则 UV 岛与贴图对不上。

## 3. 装备特有的两件"动作"事

**A. 持握 / 穿戴姿态（display）** —— 比建模更容易出错：

- 物品模型的手在 `(8,8,8)`；**握把中心必须对齐到模型原点**，否则手会握在刃身中段或悬空。
- 长武器（剑/长柄/枪）必须用 `big_handheld` 一类的 display 预设；短刃用 `handheld`。
- 穿戴件没有 display，靠**骨骼绑定**：部件挂在 `head/body/arm/leg` 骨上，跟随转头、摆臂、潜行、骑乘。
- 姿态要么用原版预设，要么显式给 `rotation / translation / scale`，不要"看着差不多"。

**B. 装备动画** —— 装备也可能动，但只做这几类：

- 面甲 / 护目镜开合（单轴旋转 + 定格）
- 武器旋转、悬浮、拖尾（循环）
- 护甲部件摆动（裙甲、披风、链饰，跟随走路的次级运动）

要求：循环动作首尾同姿态；曲线用 `catmullrom`，打击/开合瞬间用 `linear`；导出前 `validate_animations`。手持姿态与动画的细节见 `references/display-and-animation.md`。

## 4. 故障对照表

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 手/脚上有黑方块 | 分层贴图只挖了侧面，**没挖"断面"**（盒子底面那格） | `references/armor.md` 的 64×32 区域表 |
| 装备在游戏里看不见 | 被原版护甲层（皮肤 +1.0）包住 | 该件再外扩；或整套改纯 3D |
| 拖视角时闪 | 两件共面 | `fix_z_fighting` + 导出烘 inflate，或相邻件重叠 1 |
| 比 Blockbench 胖 | 外扩做了两遍（顶层 `deformation` + 自己的 clearance） | 只留一处 |
| 左右不一样 | 左右各自取整 | 导出只取一侧做镜像 |
| 只穿护腿却显示整套 | 槽位可见性按**骨骼**而不是按**部件**判断 | 按部件所属槽位开关 |
| 握把位置怪 / 手悬空 | 握把中心没对齐模型原点 | 见 `references/weapon.md` |
| 贴图拉伸/糊 | 尺寸不是整数像素 | 全部对齐整数、最小边 1 |
| 面是纯黑 | UV 采到透明像素（打包后改尺寸 / 薄件零面积） | 重打包 + 重新上色 |
| 改了没生效 | 客户端模型/贴图不热重载 | 重启客户端 |

## 5. 参考

- `references/armor.md` —— 穿戴件：原版层几何、脸/手/断面窗口、分层与纯 3D 的取舍、槽位。
- `references/weapon.md` —— 手持件：握把对齐、display 预设、2D 图标与 3D 模型的分工。

## 附录 A · 穿戴件（分层贴图与 3D 装饰件）
护甲是 mod 美术里最容易翻车的一类，因为它**同时**受两套系统约束：64×32 的 `layer_1/2` 穿戴层，和 128×128 的 3D 装饰件图集。

## 0. 先选路线：分层 / 纯 3D / 混合

| 路线 | 做法 | 适用 | 代价 |
|---|---|---|---|
| 分层 | 只画 `layer_1/2`，不做 3D | 布甲、轻甲、贴图质感为主 | 没有剪影，肩甲/裙甲做不出来 |
| 纯 3D | `layer_1/2` **全透明**，全部用 3D 件覆盖身体 | 重甲、部件数可控（≥35 件） | 3D 必须盖全身体，手/脸按设计留空 |
| 混合 | 分层画主体 + 3D 只做轮廓件 | 绝大多数情况 | 3D 件必须躲开护甲壳（见下） |

**混合路线的核心矛盾**：原版护甲层是用 `CubeDeformation(1.0)` 画的，即**比皮肤外扩 1 单位**。3D 件在 Blockbench 里看不到这层壳，按皮肤尺寸建的件进游戏会被整个包住——表现就是"看不见""黑色方块""穿模闪烁"。

- 混合：贴身件要在壳外 **再凸 0.6~1.0**（X/Z 轴，**不要动 Y**：Y 外扩会把手腕/脚踝盖住）。
- 纯 3D：`layer_1/2` 全透明后没有壳，3D 件按皮肤 +0.5 就够，轮廓立刻瘦一圈，也不会再有穿模。
- 两种都要记住：**外扩必须在 `pack_uv` 之前**烘进几何，打包后改尺寸会让 UV 错位。

## 1. `layer_1/2` 是 64×32，六个面各有固定位置

以手臂盒（起点 `(40,16)`，尺寸 4×12×4）为例：

| 面 | 贴图矩形 | 对应部位 |
|---|---|---|
| 顶面 | `(44,16) 4×4` | 肩头 |
| **底面** | **`(48,16) 4×4`** | **手的断面（最常漏挖 → 手上黑方块）** |
| 右侧 | `(40,20) 4×12` | 外侧 |
| 正面 | `(44,20) 4×12` | 前侧 |
| 左侧 | `(48,20) 4×12` | 内侧 |
| 背面 | `(52,20) 4×12` | 后侧 |

侧面那 12 行 = 手臂 12 个单位（世界 y 24→12），**手只占最后 2~3 格**。

腿盒（起点 `(0,16)`）：顶面 `(4,16)`、底面 `(8,16)`；靴子包住脚时脚底断面通常**不挖**（靴子本来就覆盖脚）。

### 必须挖空的窗口

| 部位 | 矩形 | 说明 |
|---|---|---|
| 脸 | `(8,9)-(16,15)` | 不挖看不见脸 |
| 右手 | `(40,27)-(56,32)` | 侧面四格 |
| 右手断面 | `(48,16)-(52,20)` | **漏了就是黑方块** |
| 左手 | 镜像到 `(32,27)-(48,32)` 区域 | 与右手同构 |

挖的时候用**硬边**（无抗锯齿）：半透明像素会被当成镂空，边缘出锯齿。

## 2. 3D 件与槽位

- 一件护甲只在它自己的槽位显示。判断要**按部件所属槽位**，不要按骨骼：腿骨上既有护腿件（大腿/胫甲），也有靴子件；肩甲和臂甲挂在身体骨和手臂骨，但都属于胸甲槽。
- 否则会出现"只穿护腿却把整件胸甲画出来"。

## 3. 部件预算（实测下限）

| 类型 | 部件下限 | 说明 |
|---|---|---|
| 穿戴甲（`HumanoidModel` 子类） | ≥ 35 个 cube | 低于这个数看起来就是"贴了几块板" |
| 装饰件占比 | ≥ 15% | 纯主体没有细节感 |
| 贴图 | 图标 16×16、`layer_1/2` 64×32、装饰图集 128×128 或 128×256 | 图集尺寸必须与 `LayerDefinition.create(mesh, W, H)` 一致 |

> 图集变大（>128×128）时，`LayerDefinition` 的尺寸必须跟着改，否则 UV 整体错位——这是加部件后最常见的"突然全糊了"。

## 4. 自检

```bash
# 分层窗口是否挖对（脸/手/断面）
python tools/check-armor.py --set <套装名>
```

检查项：层尺寸 64×32、手部底面与底部三行是否全透明、装饰件是否完全埋在壳里、手臂件是否下探到手、左右是否互为镜像、box-UV 面是否采到透明像素。

纯 3D 路线下 `layer_1` 全透明，检查器会自动跳过壳相关项。

## 附录 B · 手持件（握把与 display）
## 1. 握把对齐（最常见的"手悬空/握在刃上"）

- 物品模型渲染时先 `translate(0.5) + display`，**手就在模型坐标原点**。
- 所以：**握把中心必须在模型原点 (0,0,0)**，y=8 是物品模型的"原点平面"，握把中点要对齐到它。
- 长柄武器整根长度按原版量级：短剑 16、剑 20、巨剑 26、长柄 38、匕首 12（单位 = 1/16 方块）。长度变了要**平移**，不是放大。
- 握把位置错了的表现：手悬在剑柄旁边、握在刃身中段、武器横着飞出去。

## 2. display 预设

| 类型 | display | 说明 |
|---|---|---|
| 短刃 / 单手剑 | `handheld` | scale 1.0~1.2 |
| 长剑 / 巨剑 / 长柄 / 长枪 | `big_handheld` | 靠平移撑长度，**不要放得更大** |
| 盾 / 饰品 | `handheld` 或自定义 | 需要自定义时显式写 rotation/translation/scale |

- 手持模型**不要**在模型里预先把武器旋转 45°——旋转交给 display，几何保持轴对称或沿 y 轴向上，否则在 GUI 里会歪。
- 同一把武器若要 GUI 图标，另出一张 2D `_gui.png`，不要让 3D 模型兼职图标（3D 渲染做图标既糊又慢）。

## 3. 形体分层（避免"一个方块 + 一张贴图"）

至少要有：主体（刃/头/杆）→ 结构件（护手、箍、铆钉、缠绳）→ 装饰件（宝石、刻纹、流苏、配重）。

- 刃身用**分段**而不是一整块：每段独立 cube，UV 各占一块，贴图才能画出刃口亮线。
- 单侧对称的武器（如单刃斧）只建一侧再镜像；完全对称的武器必须严格镜像。
- 尖端做 2~3 级收窄，平头的剑看着像木板。
- 部件数参考：3D 武器装备件一般 ≥15 个 element（低于这个数就是"棍子 + 刀片"）。

## 4. 与注册/贴图的衔接

- 注册名 → 贴图路径 → 模型路径必须同名：`<modid>:<name>` → `assets/<modid>/textures/item/<name>.png` + `models/item/<name>.json` + `lang` 条目。
- 3D 模型的贴图用**一套图集**（64×64 或 128×128），所有部件 UV 都在这张图里；不要每个部件一张 PNG。
- 图集尺寸写在模型的 `texture_size` 里，与导出脚本一致；改了图集尺寸要同步改模型。

## 5. 自检

- [ ] 握把中心在原点，`display` 用对了预设
- [ ] 模型长度符合原版量级，没有靠 scale 硬撑
- [ ] 刃/头有分段收窄，不是单块方块
- [ ] 图集尺寸、`texture_size`、导出的 PNG 三者一致
- [ ] 游戏内手持位置正确（这是唯一可信的验收，需要用户截图）

## 附录 C · 持握姿态与装备动画
## 1. display 变换

装备的"动作"首先是静态姿态。能背原版预设就别自己调；必须自定义时，四项都要给：

```json
"display": {
  "thirdperson_righthand": {
    "rotation":    [0, -90, 55],
    "translation": [0, 1, 0.5],
    "scale":       0.85
  }
}
```

- `rotation` 用角度，顺序 Z·Y·X；长剑类常用的 `[0,-90,55]` 是"剑尖朝上、刃朝外"。
- `translation` 以 **16 = 1 方块**为单位，位移量通常很小（0~2）；靠大位移对位置说明几何本身没对齐。
- `scale` 用来适配长度档位，不要用来"修正握把位置"。
- 穿戴件没有 display：姿态 100% 来自骨骼绑定（`head/body/arm/leg`），骨骼原点必须和原版一致。

## 2. 装备动画的类型

| 动作 | 用法 | 长度 | 循环 |
|---|---|---|---|
| 面甲 / 护目镜开合 | 单轴旋转，开到底定格 | 0.4~0.6 s | once 或 hold |
| 武器旋转 / 悬浮 | 单轴匀速，或上下浮动 | 1.5~3 s | loop |
| 裙甲 / 披风 / 链饰摆动 | 小角度往返 + 相位差 | 跟随走路周期 | loop |
| 能量/发光脉动 | 缩放或贴图动画，不要改几何 | 1~2 s | loop |

- 装备动画**只做次级动作**：主体位移交给玩家动作（走路/挥砍），模型里不要再加大幅位移，否则叠加起来会穿模。
- 链饰、流苏这类悬挂件做成骨链（每节一个骨），摆动才有跟随；整根一个骨只会僵直前甩。
- 循环动作结尾必须与开头同姿态；曲线用 `catmullrom`，开合/打击瞬间用 `linear`。

## 3. 导出与校验

- 导出前跑一次 `validate_animations`：键越界、键冲突、地面穿透、部件脱离都要清零。
- `sample_pose` 可以在不渲染的情况下取任意时刻的骨骼姿态，用来核对"到底转了多少度"。
- 装备动画多数走 GeckoLib / Bedrock 格式；这两种格式的骨名与缩放约定不同，导出后要在游戏内看一次，别只看 Blockbench 预览。

## 4. 常见问题

| 现象 | 原因 |
|---|---|
| 游戏里比 Blockbench 里"翻了个方向" | display 的 rotation 与模型自身朝向叠加，模型应保持朝向 -Z |
| 手持位置对，但挥砍时穿模 | 装备动画加了位移，与玩家动作叠加 |
| 面甲开合时穿进头盔 | 转轴不在铰链位置；铰链要放在开合边的实际旋转中心 |
| 链饰甩得像硬棍 | 整根只有一个骨，或每节没有相位差 |

## 附录 D · 交付前清单
按顺序过，任何一项不过就不算完成。

## A. Blockbench 项目内

- [ ] `check_model`：`coplanar_overlap` = 0、`hidden_cube` = 0、`zero_uv` = 0、`floating_part` = 0（有意悬空件除外）
- [ ] 所有 cube 尺寸为整数、每条边 ≥ 1
- [ ] 外扩（clearance）已在 `pack_uv` **之前**完成
- [ ] 左右件由单侧镜像，位置完全对称
- [ ] 贴图在项目内（不是外部 PNG 链接），`detail_cubes` 上色，无纯色填充块
- [ ] `save_project` 到 `docs/models/<name>.bbmodel`
- [ ] 截图两张：正视图 + 四分之三视图（留档用）

## B. 装备类型专项

**穿戴件（护甲 / 饰品）**

- [ ] 骨架用原版人形六骨，原点与原版一致
- [ ] 走分层：脸、手、**手部断面**窗口 alpha = 0；脚底断面按设计取舍
- [ ] 走纯 3D：`layer_1/2` 全透明，且 3D 件覆盖全身（手/脸按设计留空）
- [ ] 槽位可见性按**部件**判断，不按骨骼
- [ ] 部件数 ≥ 35，装饰件占比 ≥ 15%

**手持件（武器 / 工具）**

- [ ] 握把中心对齐模型原点
- [ ] display 用对预设（短刃 `handheld` / 长武器 `big_handheld`）
- [ ] 长度按原版量级，没有靠 scale 硬撑

## Token 预算（经验值）

| 做法 | 影响 |
|---|---|
| 一次调用塞 40+ 个 cube | 单次返回可占数万 token，改用 `execute_script` 只回计数 |
| 每步都截图 | 每张图约 1–2k token，只在需要判断时拍 |
| 反复读整份生成的 Java | 用 `grep`/行号定位 |
| 盲改 | 最贵：一次盲改 = 全量重打包 + 重上色 + 重编译，改三轮就是几十万 token |

**结论：宁可在建模前多问一句，也不要在游戏里试错。**
